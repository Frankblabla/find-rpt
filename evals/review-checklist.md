# Lightweight report-output review

Use only the selected original PDF. Record run ID, skill/config identity, reviewed
pages, observations and pass/fail/unavailable per item. This checklist is not an
answer key. Do not run a model or expand evaluation without the authorized budget.

- Does the selected subject match the requested ticker, rather than a peer mention?
- Are conflicting periods, figures, names, or source statements preserved and
  explicitly flagged, rather than silently repaired? Check the original wording.
- Does the brief cover all material changed metrics and years in the revision
  table before optional unchanged/contextual rows? Record any omission and why.
- For each factual clause and numeric field, do its highlights include the relevant
  sentence or cells plus year, units, old/new, consensus and rate labels? Separate
  valid coordinates from semantic support. Check reported rates at their source,
  and calculated rates against their inputs; allow rounding differences explicitly.
- Are directly juxtaposed broker/consensus comparisons surfaced with the report's
  definitions and any uncertainty? Are unrelated EPS definitions kept distinct?
- Are drivers distinguished from general investment commentary and inference?
  Is report context or a management conversation actually established?
- Is broker shorthand explained or replaced with plain language supported by the
  report, including product identity where that detail is necessary?
- Are percentage-valued changes shown as percentage points? Are every material
  changed metric group and fiscal year accessible without an arbitrary row cap?
- Is any analyst escalation specific, sourced, draft-only, and appropriately triggered?

A deterministic citation-ID or formatting test does not establish the above
semantic criteria. Preserve old output and record unresolved failures separately.

For version-3 comparison plans, independently compare the declared groups with
the full original grid: every metric and fiscal-year column, including unchanged
broker/consensus pairs. Confirm each linked row's values and field labels; test
the generated source union includes the last-year value cells. Group consistency
is not evidence that a report row omitted entirely by extraction was discovered.
Also check a no-revision/no-consensus report: empty groups and missing old values
should not fabricate changes or trigger an unnecessary draft. Review the expanded
prose for faithful financial terminology and count the actual displayed words.

- For non-fiscal target rows, preserve sourced ADR/currency/month qualifiers;
  reject missing forecast periods and unsupported qualifiers. Record an offline
  revalidation separately from the original failed fresh attempt.
- Count locally generated comparison/contact wording within the 220-word limit;
  preserve every mandatory fact and reject genuine overflow without truncation.

- Check every factual clause in an expandable note against the lines that the note
  actually highlights, including other measures/years/values. Valid row sources
  alone do not establish an additional note claim.
- Read the whole analyst contact block. A selected email recipient never proves
  that phone or other contact methods are absent.
- Read rating-policy exceptions, banding and scope before classifying a generic
  threshold as a company-specific contradiction. Retain real substantive conflicts.
- For linked follow-ups, verify a completed same-report parent, saved parent ID,
  grounded answer links, and exclusion of prior generated prose from model evidence.
- Label the positive email evaluation synthetic even when a real model extracts it.
  Verify unexplained dividend-only question, stated earnings cause, correct/TODO
  recipient, fixed sender, source links, no send endpoint and isolated run storage.
